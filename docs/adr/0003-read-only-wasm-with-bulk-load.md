# ADR-003: WASM API を読み取り専用にし、データは一括ロードで受け取る

## Status

Accepted

ADR-001 の「OPFS を主要な永続化先とする」「成功条件」、および想定用途の一部を置き換える。

## Context

ADR-001 では、ブラウザ内で CREATE / INSERT / UPDATE / DELETE を行い、書き込みのたびに OPFS へ永続化する構成とした。

実装してみると、ブラウザ側で書き込みを扱うことに次の負担があることが分かった。

* 書き込みのたびにページイメージ全体を OPFS へ書き出すため、データ量に比例したコピーと I/O が発生する
* 複数タブで同じ DB を開くと、各タブが別々のメモリ上のコピーを持ち、最後に書いたタブが他の変更を上書きする
* エンジン側のメモリと OPFS の内容が食い違う可能性がある
* WASM での panic はインスタンスを復旧不能にするため、入力の種類が多いほど防御すべき箇所が増える

一方、想定している使い道では、ブラウザ内でテーブルを作成・更新したい場面は少ない。
主な使い道は、サーバーの API などから受け取ったデータを、ブラウザ内で SQL により検索・集計することである。

事前にビルドしたイメージを静的に配る方式も検討したが、データの更新やユーザーごとのデータに合わせてビルドと配信を運用する想定が立たないため採用しない。

## Decision

WASM から公開する API を読み取り専用にする。

* データは JavaScript から、テーブル定義と行の配列として**一度だけ**受け取る（一括ロード）
* 一括ロードでページイメージを組み立てた後は、`SELECT` だけを受け付ける
* SQL から `CREATE TABLE` / `INSERT` / `UPDATE` / `DELETE` を取り除く。これらの文は読み取り専用エラーとして拒否する
* OPFS は書き込みの保存先ではなく、**組み立て済みイメージのキャッシュ**として使う。キャッシュはアプリが渡すデータのバージョンをキーにする
* キャッシュは消えてもよい前提とする。キャッシュが無い・壊れている場合は、元データから組み立て直す
* 事前ビルド（ネイティブでイメージを作って配る方式）は提供しない

ページベースのストレージ（ADR-002）は維持する。一括ロードもページを確保して行を詰める形で実装する。

```text
JavaScript / TypeScript
  ├─ Database.open({ name, version, load })
  │    ├─ OPFS に同じバージョンのイメージがある → そのまま開く
  │    └─ ない → load() で元データ取得 → 一括ロード → OPFS に保存
  └─ db.query(sql, params)
          │
          ▼
       WASM API (fromTables / fromImage / query)
          │
          ▼
   Rust RDB Engine (一括ロード + SELECT のみ)
```

## Alternatives

### 事前ビルドしたイメージを配る

起動が速く、WASM 側に一括ロードも不要になる。
一方、データの更新ごとにビルドと配信が必要で、ユーザーごとのデータにも対応しにくい。
運用のイメージが立たないため採用しない。

### ブラウザ内で書き込みを扱い続ける（ADR-001 のまま）

Local-first 用途には必要になる。
一方、上記の負担に対して、想定する使い道での必要性が低いため採用しない。

## Consequences

### Positive

* 書き込みごとの OPFS 書き出し、複数タブでの上書き、メモリとディスクの不整合が無くなる
* SQL と実行器の表面積が減り、WASM で panic し得る経路が減る
* データが不変になるため、将来のインデックス（B+Tree）はソート済みデータからの一括構築で作れる
* サーバー側は既存の API が JSON を返せばよく、特別なビルド工程が要らない

### Negative

* ブラウザ内での書き込みを前提とする用途（Local-first、オフラインでの編集）には使えない
* キャッシュが無い初回起動では、ブラウザで一括ロードする時間がかかる
* データ全体を WASM のメモリに載せるため、扱えるデータ量はメモリで制限される
* トランザクション / WAL / クラッシュリカバリはブラウザ側では不要になり、学習対象としての優先度が下がる

## Success Criteria

ブラウザ内だけで以下が動作することを目標とする。

```ts
const db = await Database.open({
  name: "app",
  version: "2026-09-24",
  load: async () => ({
    todos: {
      columns: [
        { name: "id", type: "INTEGER", primaryKey: true },
        { name: "title", type: "TEXT" },
        { name: "done", type: "BOOLEAN" },
      ],
      rows: [[1, "Build a database", false]],
    },
  }),
});

const rows = db.query("SELECT * FROM todos WHERE done = ?", [false]);
// -> [{ id: 1, title: "Build a database", done: false }]
```

同じバージョンで再読み込みした場合、`load()` を呼ばずに OPFS のキャッシュから開けることを完成条件とする。
